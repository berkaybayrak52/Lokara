## 1. Zweck

Renders one engine result (`docs/03` NK engine + heating/CO₂ module) into **three documents**: the **Mieter-Einzelabrechnung** (one per tenancy, containing only that tenant's data, closing with advances paid − share = Nachzahlung/Guthaben), the **Vermieter-Gesamtübersicht** (one per object and period, all parties plus the owner's residual and the reconciliation), and the **Leerstandsaufstellung** (annex to the Gesamtübersicht, the vacancy share per cost type as a Werbungskosten record). This page specifies the *documents*, not the allocation math; every cent printed comes from the engine and is never recomputed here.

### Conventions — not law, `verify-before-production`

- **[KONVENTION]** **Höhe der fiktiven Belegung bei Leerstand.** Literature and instance case law split between „1 Person" (LG Krefeld; Schmidt-Futterer § 556a Rn. 76) and „durchschnittliche Belegungszahl der Einheit" (AG Köln WuM 2002, 28; Sternel NZM 2006, 811; Wall). Our default: **last known occupancy of the unit, minimum 1, day-accurate**; configurable to „always 1". Covers both views and is the tenant-friendly side.
- **[KONVENTION]** 30-day payment window for a Nachzahlung. The claim falls due on receipt of a proper statement; the 30 days are customary, not statutory.
- **[KONVENTION]** Obligation to print the § 35a block. The tenant's entitlement is statutory; a landlord duty to itemise it on the Betriebskostenabrechnung is customary practice.
- **[KONVENTION]** Line-wise rounding as the single computation path (`docs/03` § 6). Either path is legally defensible; we bind ourselves to the one the tenant can recompute from the printed page.
- **[KONVENTION]** Pro-rata derivation of the per-tenant CO₂ amount from the tenant's heating share. NOTE: the *disclosure* is mandatory (§ 7 Abs. 3 CO2KostAufG); only the derivation method is our choice.
- **[KONVENTION]** Printing the object-level denominator (e.g. `70.810 m²-Tage`) on the tenant copy. Required by our own verifiability standard, not by the four formal minimums.
- **[KONVENTION]** The Leerstandsaufstellung as a document. **No statute prescribes it.** What is mandatory is the taxpayer's burden of proof (§ 90 AO). Never market it as „gesetzlich vorgeschrieben" — correct wording: „erfüllt Ihre Nachweispflicht gegenüber dem Finanzamt".
- **[KONVENTION]** Wording `rechtskonform`, never `rechtssicher`, on every output.
- **[KONVENTION]** Degree-day table (VDI) when a tenant change has no interim meter reading — inherited from the heating module.

## 4. Formel

Rounding rule used throughout: **`round_half_up` to whole cents, once per printed line, never on an already-rounded value.** No line is recomputed from a rounded aggregate. Percentages are printed with two decimals but never used as an intermediate.

### D0 — Fiktivbelegung bei Leerstand (runs BEFORE denominators are formed)

```
for each Leerstandsperiode L of a unit:
  if modus == letzteBelegung: fiktivPersonen = max(1, wohnung.letzteBelegungPersonen)
  if modus == immer1:         fiktivPersonen = 1
  if modus == keine:          fiktivPersonen = 0   // only with logged confirmation
  nPersTage += fiktivPersonen × L.tage
```

Area and unit denominators are untouched — they are already period-based (`gesM2 × nTage`), so vacancy falls to the owner automatically (BGH VIII ZR 159/05). Consumption denominators are untouched — a vacant unit consumes nothing.

### D1 — select document type

```
audience == TENANT  → Mieter-Einzelabrechnung for exactly one tenancyId
audience == OWNER   → Vermieter-Gesamtübersicht for the whole object
audience == TAX     → Leerstandsaufstellung (annex to the Gesamtübersicht)
```

All three read the same engine result. **No recalculation.** A tenant document that cannot resolve its `tenancyId` must fail, never fall back to the owner view.

### D2 — Mieter-Einzelabrechnung, section order (fixed)

```
[A] Anschreiben (page 1, separate sheet)     → content spec in docs/03 § 10
[B] Kopf / Bezugsdaten
[C] Kostentabelle (one row per cost position)
[D] Zwischensumme "Ihr Anteil an den Betriebskosten"
[E] Heizkosten-Verbrauchsnachweis (only if heating present)
[F] CO₂-Kasten (only if fuel-based heating)  → Pflichtangaben § 7 Abs. 3 CO2KostAufG
[G] Vorauszahlung → Saldo
[H] § 35a-Block (only if > 0)
[I] Zahlungsdetails / Erstattungshinweis
[J] Rechtshinweise (§ 556 Frist, Einwendungsfrist, Belegeinsicht)
[K] Disclaimer + Rechtsstand-Fußzeile
```

### D3 — [C] cost line and its reference totals

`anteilCent` is the engine value (already line-wise rounded). `verteilungstext` and `bezugstext` per key:

| Schlüssel | verteilungstext | bezugstext (which reference totals accompany which key) |
| --- | --- | --- |
| Wohnfläche | nach Wohnfläche | Ihre Wohnfläche {wf} m² × {tage} Tage = {m2Tage} von {nM2Tage} m²-Tagen (Gesamtfläche {gesM2} m² × {nTage} Tage) |
| Personenzahl | nach Personen | {personen} Person(en) × {tage} Tage = {persTage} von {nPersTage} Personentagen |
| Wohneinheiten | je Wohneinheit | 1 von {anzWE} Wohneinheiten · {tage} von {nTage} Tagen |
| Wasserverbrauch | nach Verbrauch | Ihr Verbrauch {v} m³ von {nWasser} m³ Gesamtverbrauch (Summe aller erfassten Einheiten) |
| Heizkosten (Messdienst) | lt. Messdienst | Abrechnung {messdienstName}, Beleg-Nr. {belegNr} — Einzelnachweis siehe Abschnitt [E] |
| Heizkosten (Ersatzverteilung) | ersatzweise nach Wohnfläche | as Wohnfläche + mandatory note „Für Ihre Einheit lagen keine Verbrauchswerte vor." |
| Direktzuordnung | direkt Ihrer Wohnung zugeordnet | {tage} von {nTage} Tagen |

**Rule:** `bezugstext` never names another tenant. Object-level denominators are permitted and required — they are aggregates, not personal data.

**Rule:** the sum of all tenants' `bezugMieter` is smaller than the printed denominator whenever the object had vacancy. That gap is the owner's share and is **not** explained on the tenant copy beyond the totals themselves.

### D4 — [D] Zwischensumme

```
anteilGesamtCent = Σ anteilCent over all printed lines   // integer addition, no rounding
```

### D5 — [G] Vorauszahlung → Saldo (the block that was missing)

```
saldoCent = anteilGesamtCent − vorauszahlungGesamtCent    // integer, exact

saldoCent > 0  → "NACHZAHLUNG"
   Ihr Anteil an den Betriebskosten ...........  {anteilGesamt} €
   Ihre geleisteten Vorauszahlungen ............ −{vorauszahlung} €
   ───────────────────────────────────────────────
   Nachzahlung .................................  {saldo} €

saldoCent < 0  → "GUTHABEN", amount = |saldo|
   Guthaben zu Ihren Gunsten ...................  {|saldo|} €

saldoCent == 0 → "AUSGEGLICHEN"
   Es ergibt sich weder eine Nachzahlung noch ein Guthaben.
```

Advance payments are always shown as a negative line so the tenant can verify with a pocket calculator.

### D6 — [E] heating verification block

```
Gerät | Nummer | Stand {von} | Stand {bis} | Verbrauch | Einheit | Ablesedatum
Verbrauch = standEnde − standAnfang    // standEnde < standAnfang → hard error, no wrap-around

Grundkosten  {grundProzent} % ..... {betrag} €   (verteilt nach m²-Tagen)
Verbrauchsk. {100−grundProzent} % . {betrag} €   (verteilt nach {HKV-Einheiten|kWh|m³})
```

If no interim reading existed and the degree-day table was used, this line is mandatory: „Ihr Verbrauchsanteil wurde nach der Gradtagszahltabelle zeitanteilig ermittelt (keine Zwischenablesung)." **[KONVENTION]**

### D7 — [F] CO₂ box

```
1. co2Kg             = Σ invoice CO₂   (fallback: menge_kWh × faktor + warning)
2. spezifisch        = round(co2Kg / gesamtflaecheM2, 2)     kg CO₂/m²/a
3. stufe             = lookup(spezifisch) → vermieterProzent
4. co2AbzugVermieter = round_half_up(co2KostenCent × vermieterProzent / 100)
5. co2MieterGesamt   = co2KostenCent − co2AbzugVermieter
6. co2AnteilMieter   = round_half_up(co2MieterGesamt × heizGesamtMieter / Σ heizGesamtAlleMieter)
```

Steps 1–5 are printed on the tenant copy and the owner overview. **Step 6 is a Pflichtangabe under § 7 Abs. 3 CO2KostAufG** — omitting it (or the Einstufung, or the Berechnungsgrundlagen) gives the tenant a 3 % reduction on the whole heating cost (§ 7 Abs. 4). Only the pro-rata *method* in step 6 is a [KONVENTION].

### D8 — [H] § 35a block

```
anteil35aCent = Σ round_half_up(anteilCent_line × lohnanteilCent_line / gesamtbetragCent_line)
if anteil35aCent == 0 → omit section [H] entirely (no zero line)
```

Formula source: `docs/03` § 7. Not restated here — single source of truth.

### D9 — [J] legal notices, computed

```
abrechnungsfristEnde = periode.bis + 12 Monate               (§ 556 Abs. 3 S. 2 BGB)
einwendungsfristEnde = zugangsdatum + 12 Monate              (§ 556 Abs. 3 S. 5 BGB)
                       zugangsdatum unknown at print time → print the rule, not a date
nachforderungGesperrt = (erstelltAm > abrechnungsfristEnde) AND NOT vermieterNichtZuVertreten

[J1] "Abrechnungszeitraum {von} – {bis}. Die Abrechnungsfrist nach § 556 Abs. 3 BGB
      endet am {abrechnungsfristEnde}."
[J2] "Einwendungen gegen diese Abrechnung können Sie innerhalb von zwölf Monaten nach
      Zugang geltend machen (§ 556 Abs. 3 BGB). Danach sind Einwendungen ausgeschlossen,
      es sei denn, Sie haben die verspätete Geltendmachung nicht zu vertreten."
[J3] "Die Belege können Sie nach Terminvereinbarung einsehen: {kontakt}."
[J4] if nachforderungGesperrt:
     "Diese Abrechnung wird Ihnen nach Ablauf der Frist des § 556 Abs. 3 BGB übersandt.
      Eine Nachforderung wird hiermit nicht geltend gemacht."
     → replaces section [I]; the Saldo is still printed, label becomes "Rechnerischer Saldo".
     → gate applies ONLY to saldoCent > 0. A Guthaben stays payable.
```

### D10 — [K] disclaimer + footer (fixed placement)

```
Fußzeile jeder Seite: "Erstellt mit Lokara · Rechtsstand {version} · Seite x von y"
Schlussblock: "Diese Abrechnung wurde maschinell erstellt und ist ohne Unterschrift gültig.
               Lokara erstellt rechtskonforme Abrechnungen, ersetzt jedoch keine Rechts-
               oder Steuerberatung."
```

The word `rechtssicher` is forbidden in all outputs. Layout rule, not design: the block [G] must not be separated from [D] by a page break; the cost table breaks only between complete cost rows.

### D11 — Vermieter-Gesamtübersicht, what differs

|  | Mieter-Einzelabrechnung | Vermieter-Gesamtübersicht |
| --- | --- | --- |
| Parties shown | exactly one | all tenancies, by name |
| Addressee block | tenant name + delivery address | none (internal) |
| Per cost type | total + own share | total + share per tenancy + Eigentümeranteil |
| Leerstand | never mentioned | own column per cost type + link to the Leerstandsaufstellung |
| Reconciliation | none | Σ umgelegt + Eigentümeranteil = Gesamtkosten — mandatory, must balance to 0 |
| Saldo | own Saldo only | all Saldi + Σ Nachzahlungen, Σ Guthaben |
| § 35a | own amount | per tenancy |
| Payment details | printed | not printed |
| Legal notices | [J1]–[J4] | [J1] only |
| Watermark | none | INTERN — nicht an Mieter versenden |

**Hard rule:** the owner overview is never generated into the same PDF file as a tenant document and never into the tenant's e-mail/portal channel. The tenant portal exposes exactly one document ID per tenancy.

### D12 — Leerstandsaufstellung (third document, audience landlord / Steuerberater)

